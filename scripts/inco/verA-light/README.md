# verA-light (multi_raffle_inco_a_light)

End-to-end guide for deploying and testing the **verA-light** raffle variant:

- Program: `multi_raffle_inco_a_light` (Rust / Anchor)
- Features: LIGHT zk-compressed slots **+** commit-reveal **+** Inco Lightning FHE check
- Scripts: `host.ts`, `join.ts`, `draw.ts`, `reveal.ts`, `claim.ts`, `generate-ligh-proof.ts`, `generate-reveal-proof.ts`

---

## 1. Prerequisites

- **Solana CLI** installed and configured
- **Anchor** CLI `0.31.1`
- **Node** (via `nvm`), **bun** for running scripts
- **Devnet wallet** at `~/.config/solana/id.json` with **> 3.1 SOL**
- **Helius devnet RPC** (or other RPC that supports ZK Compression)
- **Light stateless client** already installed in this repo:
  - `@lightprotocol/stateless.js`
  - `@solana/web3.js`

> Note: For verA-light we do **not** use the old `zk-compression-cli prove` flow. Instead we call the Light stateless client directly from `generate-ligh-proof.ts` against your Helius devnet RPC.

## 3. LIGHT proof data (`light-proof.json`)

The commit-reveal flow requires **two** LIGHT validity proofs:

1. **Join proof** for *new slot addresses* (`light-proof.json`)
2. **Reveal proof** for *existing compressed slot* (`reveal-proof.json`)

The updated instructions are:

- `unsafe_join_raffle(slot_ids, commitments, amount, proof, address_tree_info, output_state_tree_index, system_accounts_offset)`
- `finalize_winner(slot_id, salt, proof, state_tree_info, system_accounts_offset)`

### 3.1. Join proof (`light-proof.json`)

Generated by `generate-ligh-proof.ts` and consumed by `join.ts` / `join-test.ts`.
Example shape:

```jsonc
{
  "slotIds": [1, 2, 3],
  "proof": { "0": "<compressedProof-bytes-from-Light>" },
  "addressTreeInfo": {
    "rootIndex": 0,
    "addressMerkleTreePubkeyIndex": 0,
    "addressQueuePubkeyIndex": 0
  },
  "outputStateTreeIndex": 0,
  "systemAccountsOffset": 0,
  "remainingAccounts": [
    { "pubkey": "<pubkey>", "isSigner": false, "isWritable": true },
    { "pubkey": "<pubkey>", "isSigner": false, "isWritable": false }
  ],
  "slotAddresses": ["<compressed slot address>", "..."]
}
```

### 3.2. Reveal proof (`reveal-proof.json`)

Generated by `generate-reveal-proof.ts` and consumed by `reveal.ts`.
Example shape:

```jsonc
{
  "slotId": 1,
  "slotAddress": "<compressed slot address>",
  "proof": { "0": "<compressedProof-bytes-from-Light>" },
  "stateTreeInfo": {
    "rootIndex": 0,
    "proveByIndex": false,
    "merkleTreePubkeyIndex": 0,
    "queuePubkeyIndex": 1,
    "leafIndex": 0
  },
  "systemAccountsOffset": 0,
  "remainingAccounts": [
    { "pubkey": "<pubkey>", "isSigner": false, "isWritable": true },
    { "pubkey": "<pubkey>", "isSigner": false, "isWritable": false }
  ]
}
```

### 3.3. How to generate proofs

1. Ensure your **devnet Helius RPC** is exported:

   ```bash
   export HELIUS_RPC_URL="https://devnet.helius-rpc.com/?api-key=YOUR_KEY"
   ```

2. Host a raffle (creates `raffle-info.json`):

   ```bash
   bun run scripts/inco/verA-light/host.ts
   ```

3. Optionally set join slots in `join-config.json`:

   ```jsonc
   { "slotIds": [1, 2, 3], "amountSol": 0.1 }
   ```

4. Generate the **join** proof:

   ```bash
   bun run scripts/inco/verA-light/generate-ligh-proof.ts
   ```

5. After a slot is drawn, generate the **reveal** proof:

   ```bash
   bun run scripts/inco/verA-light/generate-reveal-proof.ts
   ```

## 4. Running the verA-light scripts

All paths below assume you run from the **repo root** and use **bun**.

### 4.1. Host a verA-light raffle

This uses `scripts/inco/verA-light/host.ts` and the Anchor IDL.

```bash
bun run scripts/inco/verA-light/host.ts
```

This script will:

- Connect to devnet via `SOLANA_RPC_URL` or the default Anchor provider.
- Use the wallet at `~/.config/solana/id.json` as the host.
- Derive PDAs for:
  - Config
  - Raffle
  - Slots
  - Treasury
- Call `unsafe_host_raffle` on `multi_raffle_inco_a_light`.
- Save a `raffle-info.json` file in this folder containing:

```jsonc
{
  "raffleId": "...",
  "configPda": "...",
  "rafflePda": "...",
  "slotsPda": "...",
  "treasuryPda": "...",
  "addressTree": "...",
  "addressQueue": "...",
  "stateTree": "...",
  "stateQueue": "...",
  "totalSlots": 1000000,
  "maxSlotsPerAddress": 100,
  "expiresAt": 0,
  "tx": "<host transaction signature>",
}
```

You can then inspect the raffle on Solana explorer using the printed PDA and tx signature.

### 4.2. Join the raffle (Anchor / verA-light)

Ensure:

- `raffle-info.json` exists (from `host.ts`).
- `light-proof.json` exists (from your Light client helper script).

Then run:

```bash
bun run scripts/inco/verA-light/join.ts
```

This script will:

- Load your CLI wallet and connect to devnet.
- Load the `multi_raffle_inco_a_light` IDL from `target/idl`.
- Read `raffle-info.json` (config/raffle/slots/treasury PDAs).
- Read `light-proof.json` (proof, tree info, remaining accounts).
- Compute per-slot commitments and save salts in `join-info.json`.
- Call:

```ts
unsafeJoinRaffle(
  slotIds,
  commitments,
  amount,
  proof,
  addressTreeInfo,
  outputStateTreeIndex,
  systemAccountsOffset,
);
```

with accounts:

- `payer`: your wallet
- `config`: config PDA
- `raffle`: raffle PDA
- `slots`: slots PDA
- `userRaffle`: PDA derived as `["user", raffle, payer]`
- `treasury`: treasury PDA
- `systemProgram`: `SystemProgram.programId`

On success, it logs the transaction signature and saves `join-info.json` with details (including salts needed for reveal).

### 4.3. Draw winner slot

```bash
bun run scripts/inco/verA-light/draw.ts
```

### 4.4. Reveal winner (commit-reveal)

1. Generate a reveal proof:

```bash
bun run scripts/inco/verA-light/generate-reveal-proof.ts
```

2. Provide `slotId` + `salt` (from `join-info.json` or `reveal-config.json`) and finalize:

```bash
bun run scripts/inco/verA-light/reveal.ts
```

### 4.5. Claim prize

```bash
bun run scripts/inco/verA-light/claim.ts
```

### 4.6. Raw-test variant (`join-test.ts`)

`join-test.ts` is a lower-level variant that also:

- Loads `light-proof.json`.
- Uses Anchor Program API (not manual instruction serialization) to call `unsafeJoinRaffle` on a previously created `raffle` from `simple-test.ts` / `test-result.json`.

Run with:

```bash
bun run scripts/inco/verA-light/join-test.ts
```

## 5. System architecture: LIGHT zk + Inco FHE

The verA-light system combines:

1. **Traditional Anchor accounts** for control & accounting:
   - `Config`: global settings (e.g. refund fee bps).
   - `Raffle`: raffle state (id, total_slots, sold_slots, status, etc.).
   - `RaffleSlots`: compact metadata + Light tree config.
   - `UserRaffle`: per-user record (ticket_count, paid).
   - `Treasury`: PDA that receives the SOL payments.

2. **Commit-reveal privacy**:
   - Each slot is stored as a **compressed account**: `CompressedSlot { raffle, slot_id, owner_commitment }`.
   - `unsafe_join_raffle` stores **commitments**, not owners.
   - `finalize_winner` verifies the commitment with a LIGHT read-only proof + salt.
   - Winner identity is only revealed after draw (delayed transparency).

3. **Inco Lightning FHE**:
   - `draw_raffle` also stores an encrypted winning slot handle.
   - `unsafe_check_winner` lets a user compare a slot id to the encrypted handle and
     decrypt the result off-chain (optional UX).
   - On-chain correctness still comes from commit-reveal + LIGHT.

4. **LIGHT zk-compression**:
   - Slots live in LIGHT merkle trees, not on-chain accounts.
   - Proofs allow creation (join) and validation (reveal) without expanding state.
